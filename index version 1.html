Property Wrappers

who owns the data, and who just borrows it

@State

Use for value types (Int, String, Bool, struct) owned by this view only. Always mark private.

@State private var count = 0
@State private var isShowingSheet = false
Forget this: @State persists across view re-creation — SwiftUI stores it outside the struct.

@StateObject

Use when this view creates the ObservableObject (you write = SomeClass()). It survives re-renders.

@StateObject private var viewModel = NewsViewModel()
If you type "= ClassName()" → it's StateObject. Always.

@ObservedObject

Use when the object is passed in from a parent, not created here. It does NOT survive if the parent re-creates it.

struct RowView: View {
    @ObservedObject var viewModel: NewsViewModel
}
Bug to avoid: using @ObservedObject at the top of a hierarchy that re-renders often → object resets unexpectedly. Use @StateObject there instead.

@Published

Goes inside an ObservableObject class. Announces changes so any observing view refreshes.

class AuthViewModel: ObservableObject {
    @Published var isLoggedIn = false
    @Published var user: User?
}
Only mark properties @Published if the UI actually reads them — extra ones cause needless re-renders.

@Environment

Reads a system value (colorScheme, dismiss action, etc.) implicitly passed down the tree.

@Environment(\.colorScheme) var colorScheme
@Environment(\.dismiss) var dismiss

Button("Close") { dismiss() }

@EnvironmentObject

Injects a shared object app-wide without passing it through every initializer. Use for auth/session/theme.

// App root
ContentView()
    .environmentObject(session)

// Any descendant, any depth
@EnvironmentObject var session: SessionManager
Crash risk: if a view expects @EnvironmentObject that was never injected above it, the app crashes at runtime. Always inject at the top (App struct).

@Binding

Gives a child view a two-way connection to a value owned by the parent. Use the $ prefix to pass it.

struct ChildTextField: View {
    @Binding var name: String
    var body: some View { TextField("Name", text: $name) }
}
// Parent: ChildTextField(name: $name)

@ViewBuilder

Lets a function/closure return multiple or conditional views stitched together — what makes body { } work at all.

struct CardContainer: View {
    @ViewBuilder let content: Content
    var body: some View { VStack { content } }
}

@ViewBuilder
func statusView(isLoading: Bool) -> some View {
    if isLoading { ProgressView() } else { Text("Done") }
}

@AppStorage

Reads/writes directly to UserDefaults — great for small persisted settings (theme, onboarding flag).

@AppStorage("hasSeenOnboarding") var hasSeenOnboarding = false

@FocusState

Tracks/controls which field is focused — programmatically show keyboard, move to next field, dismiss keyboard.

@FocusState private var focusedField: Field?

TextField("Email", text: $email)
    .focused($focusedField, equals: .email)

focusedField = .email   // sets focus programmatically
focusedField = nil      // dismisses keyboard

@Namespace

Needed for matchedGeometryEffect — shared element transitions (hero animations between views).

@Namespace private var animation

Image("thumb")
    .matchedGeometryEffect(id: "hero", in: animation)

Passing Data Between Screens / Files

Swift ↔ Swift, Swift ↔ SwiftUI, SwiftUI ↔ SwiftUI

SwiftUI → SwiftUI, read-only

Child just needs the data, won't modify it → pass as a plain let through init.

struct DetailView: View {
    let article: Article
}
NavigationLink(destination: DetailView(article: selectedArticle)) {
    Text("Open")
}

SwiftUI → SwiftUI, child modifies parent's value

Use @Binding — see Property Wrappers above.

Shared object across many views

Own once with @StateObject at the top, pass down as @ObservedObject, or use .environmentObject() for global reach.

Sending data back from a child screen

Three common patterns, pick by complexity:

// 1. Binding — simplest, same hierarchy
@Binding var selectedColor: Color

// 2. Closure callback
struct PickerView: View {
    var onSelect: (String) -> Void
}
PickerView(onSelect: { picked in self.fruit = picked })

// 3. Shared ObservableObject — best for async/complex flows
// child updates shared object, parent auto-updates via @Published

Plain Swift → plain Swift (no UI)

Ordinary Swift, no property wrappers needed unless it must trigger UI updates.

struct NetworkService {
    func fetchUser() -> User { /* ... */ }
}
class UserManager {
    var currentUser: User?
}

Plain Swift file → SwiftUI View (MVVM bridge)

Model/Service stay plain Swift. The ViewModel (ObservableObject) is the bridge.

Model (struct)
   → Service (plain Swift, fetch/transform)
        → ViewModel (@Published props, ObservableObject)
             → View (@StateObject / @ObservedObject)

Unrelated view hierarchies (deep links, tab switches)

Use @EnvironmentObject at the app root, a shared singleton service (.shared) for things like NetworkMonitor, or rarely NotificationCenter for UIKit bridging.

Combine & Async

AnyPublisher, .map, .sink, and when to use async/await instead

AnyPublisher network call, line by line

func topHeadlines() -> AnyPublisher {
    return URLSession.shared.dataTaskPublisher(for: request)
        .map(\.data)                                   // keep only Data
        .decode(type: NewsResponse.self, decoder: JSONDecoder())  // Data → Model
        .receive(on: DispatchQueue.main)                // switch to main thread
        .eraseToAnyPublisher()                          // hide the messy generic type
}
.receive(on: .main) is required before touching @Published — UI must update on main thread.

Consuming it in a ViewModel

private var cancellables = Set()

func loadHeadlines() {
    isLoading = true
    service.topHeadlines()
        .sink(receiveCompletion: { [weak self] completion in
            self?.isLoading = false
            if case .failure(let error) = completion {
                self?.errorMessage = error.localizedDescription
            }
        }, receiveValue: { [weak self] response in
            self?.articles = response.articles
        })
        .store(in: &cancellables)   // MUST store or it cancels instantly
}
Forget .store(in:) and the subscription dies the instant the function returns.

.map — general use

Transforms each emitted value, like Array.map but for a stream.

$searchText
    .map { $0.lowercased() }
    .sink { print($0) }

Debounced live search

$searchQuery
    .debounce(for: .milliseconds(300), scheduler: RunLoop.main)
    .removeDuplicates()
    .sink { [weak self] query in self?.performSearch(query) }
    .store(in: &cancellables)

.assign(to:on:)

Alternative to .sink when you just want to pipe a value directly into a property, no custom logic.

publisher.assign(to: \.articles, on: self)

async/await — the modern alternative

Prefer for one-shot calls. Use Combine for continuous streams (live search, WebSocket, SSE, multiple @Published sources).

func topHeadlines() async throws -> NewsResponse {
    let (data, _) = try await URLSession.shared.data(for: request)
    return try JSONDecoder().decode(NewsResponse.self, from: data)
}

// calling it inside a View
.task {
    do { articles = try await service.topHeadlines() }
    catch { errorMessage = error.localizedDescription }
}

View Modifiers You Always Forget

the ones that slip your mind mid-build

.onAppear vs .task

Use .task for async work (auto-cancels if view disappears). Use .onAppear for simple sync side-effects.

.task { await viewModel.load() }
.onAppear { print("appeared") }

.frame

.frame(width: 100, height: 40)
.frame(maxWidth: .infinity, alignment: .leading)

Card-style stack (padding / background / cornerRadius / shadow)

.padding(16)
.background(Color(.systemBackground))
.cornerRadius(12)
.shadow(color: .black.opacity(0.08), radius: 8, y: 4)
Order matters: padding before background so the background includes the padding.

.overlay + .clipShape (border trick)

.clipShape(RoundedRectangle(cornerRadius: 12))
.overlay(
    RoundedRectangle(cornerRadius: 12)
        .stroke(Color.gray.opacity(0.3), lineWidth: 1)
)

Conditional disabling

Button("Submit") { submit() }
    .disabled(email.isEmpty)
    .opacity(email.isEmpty ? 0.5 : 1)

.safeAreaInset — sticky bottom bar

ScrollView { content }
    .safeAreaInset(edge: .bottom) {
        Button("Continue") { }.padding()
    }

.redacted — skeleton loading state

Text(article.title)
    .redacted(reason: isLoading ? .placeholder : [])

Navigation & Presentation

sheets, alerts, nav stacks, dismiss

NavigationStack (iOS 16+)

NavigationStack(path: $path) {
    List(items) { item in
        NavigationLink(item.name, value: item)
    }
    .navigationDestination(for: Item.self) { item in
        DetailView(item: item)
    }
}
// programmatic push
path.append(newItem)

.sheet — bool vs item

.sheet(isPresented: $showSheet) { DetailView() }

// item-based — auto-unwraps, cleaner for optional data
.sheet(item: $selectedArticle) { article in
    DetailView(article: article)
}

.alert

.alert("Error", isPresented: $showError, presenting: errorMessage) { _ in
    Button("OK", role: .cancel) { }
} message: { message in
    Text(message)
}

Dismissing a sheet from inside

@Environment(\.dismiss) var dismiss
Button("Done") { dismiss() }

TabView

TabView {
    HomeView()
        .tabItem { Label("Home", systemImage: "house") }
    ProfileView()
        .tabItem { Label("Profile", systemImage: "person") }
}

Lists & Forms

ForEach, swipe actions, pickers

ForEach needs Identifiable

struct Article: Identifiable {
    let id = UUID()
    let title: String
}
List(articles) { article in Text(article.title) }
// no Identifiable? use: ForEach(articles, id: \.title)

.swipeActions

.swipeActions(edge: .trailing) {
    Button(role: .destructive) { delete(item) } label: {
        Label("Delete", systemImage: "trash")
    }
}

Picker styles

Picker("Category", selection: $selected) {
    ForEach(categories, id: \.self) { Text($0) }
}
.pickerStyle(.segmented)  // or .menu, .wheel

Form + Section

Form {
    Section("Account") {
        TextField("Email", text: $email)
        SecureField("Password", text: $password)
    }
}

Custom Binding (Binding get/set)

Use when you need to transform a value on the way in/out — e.g. binding a Double field to a String TextField.

Binding(
    get: { String(amount) },
    set: { amount = Double($0) ?? 0 }
)

Layout Tools

grids, geometry, spacing

LazyVGrid

let columns = [GridItem(.flexible()), GridItem(.flexible())]

LazyVGrid(columns: columns, spacing: 12) {
    ForEach(items) { item in CardView(item: item) }
}

GeometryReader

Use sparingly — it greedily fills available space. Good for reading parent size.

GeometryReader { geo in
    Rectangle().frame(width: geo.size.width * 0.5)
}

Spacer & alignment

HStack {
    Text("Left")
    Spacer()
    Text("Right")
}
ZStack(alignment: .bottomTrailing) { image; badge }

Animation & Gestures

withAnimation, transitions, taps and drags

withAnimation

withAnimation(.spring(response: 0.4, dampingFraction: 0.7)) {
    isExpanded.toggle()
}

.transition

if showCard {
    CardView()
        .transition(.move(edge: .bottom).combined(with: .opacity))
}

Gestures

.gesture(
    DragGesture()
        .onChanged { value in offset = value.translation }
        .onEnded { _ in withAnimation { offset = .zero } }
)
.onTapGesture { print("tapped") }
.onLongPressGesture { print("long pressed") }

Quick Decision Tables

when in doubt, scan these

Property Wrapper — which one?

SituationWrapper
Simple value owned by this view@State
Class instance created HERE@StateObject
Class instance received from parent@ObservedObject
Property inside ObservableObject that should update UI@Published
Reading system value (colorScheme, dismiss)@Environment
Shared object needed app-wide@EnvironmentObject
Child needs to write back to parent's value@Binding
Container/function returning multiple/conditional views@ViewBuilder
Small persisted setting@AppStorage
Track/control which field is focused@FocusState

Combine vs async/await — which one?

SituationUse
One-shot network fetchasync/await
Continuous stream (WebSocket, SSE)Combine
Debounced search-as-you-typeCombine
Reacting to multiple @Published sources at onceCombine (.combineLatest)
Simple sequential async callsasync/await

Presenting a sheet — bool or item?

SituationUse
Simple on/off, no associated data.sheet(isPresented:)
Need to pass a specific optional object.sheet(item:)

Passing data — which pattern?

ScenarioPattern
Child reads parent data onlyPlain let via init
Child writes back a simple value@Binding
Child sends back a one-time resultClosure callback
Many views need the same live dataShared ObservableObject
Global app state (auth, theme)@EnvironmentObject
Unrelated screens, no shared parentSingleton service or EnvironmentObject at root

Nothing matches

Try a shorter term — "state", "sheet", "publisher", "binding"…
